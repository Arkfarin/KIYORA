# 4. НОВАЯ АРХИТЕКТУРА

Используй следующую целевую модель:

Flutter Presentation Layer
↓
Flutter Application State / Repositories
↓
flutter_rust_bridge
↓
Rust FFI Adapter
↓
Existing KIYORA Rust Backend
↓
Telegram / TDLib / SQLite / Media Engine

- UI.
- Навигацию.
- Виджеты.
- Анимации.
- Пользовательские взаимодействия.
- Локальное визуальное состояние.
- Отображение данных.
- Диалоги и платформенную адаптацию.

Rust отвечает за:
- Telegram.
- TDLib.
- Авторизацию.
- Vault.
- Хранилище.
- SQLite.
- Синхронизацию.
- Очередь.
- Воспроизведение.
- Метаданные.
- Импорт и экспорт.
- Кэширование.
- Согласованность данных.
- Восстановление операций.
- Бизнес-логику.

## 4.1 Rust backend должен остаться одним

Не переписывай существующий backend на Dart.

Не создавай вторую реализацию Telegram-синхронизации.

Не дублируй музыкальную очередь во Flutter.

Не создавай независимый Dart audio player.

Не переносить декодирование аудио из Rust во Flutter без доказанной необходимости.

Основной музыкальный движок уже существует и должен продолжить работу.

Dart не должен становиться вторым источником истины.

## 4.2 Flutter Rust Bridge

Используй поддерживаемую стабильную версию flutter_rust_bridge v2, совместимую с установленными Flutter и Rust.

Создай отдельный Rust FFI crate, не зависящий от Tauri.

Например:

`src-tauri/crates/kiyora-flutter-bridge/`

Он должен предоставлять типизированный интерфейс к `vault_core::Backend`.

Не пытайся напрямую генерировать Dart API для всего внутреннего Rust workspace.

Создай ограниченный, устойчивый публичный слой.

Поддержать:
- Инициализацию.
- Завершение.
- Профили.
- Сессии.
- Авторизацию Telegram.
- Vault operations.
- Sync status.
- Library queries.
- Search.
- Playlists.
- Import/export.
- Metadata editing.
- Playback controls.
- Queue operations.
- Lyrics.
- Background events.
- Recovery и error states.

Используй типизированные Rust/Dart-модели вместо бесконтрольных JSON-строк.

Генерируемый bridge code должен воспроизводимо создаваться из репозитория.

## 4.3 Backend lifecycle

Реализуй корректный жизненный цикл:

- Единственная активная инициализация backend.
- Безопасное восстановление профиля.
- Синхронизация при подключении.
- Асинхронные команды без блокировки UI thread.
- Подписка на события.
- Отписка от событий.
- Восстановление после потери потока.
- Reconnect.
- Shutdown.
- Защита от повторных команд.
- Отмена долгих операций.
- Контроль ошибок.
- Корректное состояние после смены аккаунта.

Не допускай повторного создания аудиодвижка при обычном пересоздании Flutter Widget tree.

На Android пересоздание Activity не должно уничтожать существующую сессию воспроизведения без необходимости.

## 4.4 Безопасность миграции

Нельзя терять:
- Telegram session.
- Vault ID.
- Профили.
- SQLite database.
- Скачанную музыку.
- Playlists.
- Метаданные.
- Artwork.
- Lyrics.
- Очередь.
- Offline cache.
- Recovery journals.

Сохрани схемы данных или реализуй безопасную миграцию.

Миграция должна быть:
- Проверяемой.
- Повторяемой.
- Идемпотентной.
- С защитой от повреждения.
- С возможностью восстановления.

Особенно тщательно проверь Android application ID, signing certificate и доступ к старому app-private storage.

Не считай новую APK автоматически совместимой с обновлением старой Tauri APK.

Если Android package ID или ключ подписи меняются, реализуй отдельный безопасный механизм переноса данных.

# 7. SPOTIFY-LEVEL LYRICS

Lyrics — одна из ключевых функций.

Используй Spotify как основной референс для компоновки и поведения.

## 7.1 Синхронизированные тексты

- Крупные строки.
- Чёткий акцент на текущей строке.
- Приглушённый неактивный текст.
- Плавное изменение активной строки.
- Автоматическое следование.
- Ручная прокрутка.
- Нажатие на строку для seek, если есть временная метка.
